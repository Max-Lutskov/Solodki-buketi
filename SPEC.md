## 3. Стек

Стек, конфіги й SEO-правила — як у сусідніх проєктах `D:\Projects` (Процков Буд) і `D:\sadovi-mrii` (Садові мрії); `sadovi-mrii` — найсвіжіший, орієнтуватись на нього. **Беремо лише технічну базу** (конфіги, `lead.post.ts`, `schema.ts`, `img.ts`, скрипт фото, `.claude/skills/`). Структуру блоків, компоненти лендінгів і дизайн робимо **з нуля** — ніша інша, сайт не має бути схожим на них.

- **Nuxt 4 + Vue 3 + TypeScript (strict)**, **Nuxt UI 4 (Tailwind 4)**, `@nuxtjs/sitemap`, `@nuxtjs/robots`, `@nuxt/fonts`. Node 22 (`.nvmrc`).
- **Іконки:** `@iconify-json/lucide`, `@iconify-json/simple-icons` (Viber/Telegram/Instagram) — лише в клієнтському бандлі (`icon.serverBundle: false`, `clientBundle.scan`), бо безкоштовний Worker вміщує 3 МБ.
- **Рендеринг:** усі сторінки пререндеряться (`routeRules` з `prerender: true`), адреси **зі слешем у кінці** (`site.trailingSlash: true`), `nitro.prerender.ignore` відкидає дублі без слеша (на Windows падають з EPERM). Worker обробляє лише `/api/order`. `features.inlineStyles: true`, `ui.colorMode: false`, `ui.experimental.componentDetection`.
- **Контент:** без `@nuxt/content` (на Cloudflare Worker йому потрібна D1 — зайва складність). Загальні дані — `app/data/site.ts`. Букети — **окремий JSON-файл на букет** `app/data/bouquets/<slug>.json`, збираються через `import.meta.glob` під час білду (додати роботу = покласти файл і фото; формат зручний і для CMS на етапі 2). Тексти лендінгів — у `app/data/landings.ts`.
- **Зображення:** без `@nuxt/image` (на безкоштовному Worker немає трансформацій). Як у сусідніх проєктах: `.jpg`-оригінал для schema/OG + WebP-варіанти для `srcset`, скрипт `npm run images` (sharp), `srcset()` з `app/utils/img.ts`, `sizes` за реальною шириною. Hero — `preload` + `fetchpriority="high"`.
- **Валідація:** вручну в `server/api/order.post.ts` (як `lead.post.ts`), без zod — менший бандл.
- **SEO:** JSON-LD через `app/utils/schema.ts` (`useHead` зі script `application/ld+json`), `sitemap.zeroRuntime: true`.
- **Хостинг:** **Cloudflare Worker** (пресет `cloudflare_module`), `wrangler.jsonc` з `assets` + `custom_domain`, `workers_dev: false`, окремий Worker для переадресації `www` → без `www` (як `redirect-www/` у sadovi-mrii). Деплой: `npm run deploy`. Секрети — `wrangler secret`, локально `.env`. На Windows — `npm.cmd` / `npx.cmd`.
- **CMS (етап 2, опційно):** Decap CMS або Telegram-бот — щоб мама додавала букети з телефона. На етапі 1 — додаємо через git.
- **Аналітика:** Cloudflare Web Analytics (без cookie, тож без банера) + Google Search Console. GA4 — за бажанням, як у Процков Буд.

### 4.4 Форма «Зібрати свій» `/zibraty-svij`

Коротка форма: людина не має заповнювати анкету. **Обов'язкові лише ім'я й телефон** — решту Тетяна уточнює в розмові.

Основні поля:
| Поле | Тип | Обов'язкове |
|---|---|---|
| Ім'я | text | так |
| Телефон | tel, +380 | так |
| Де зручніше спілкуватися | radio: Viber / Telegram / Дзвінок / Instagram (за замовчуванням Viber) | — |
| Який букет потрібен | textarea одним текстом («мамі на ДН, любить Raffaello, без алкоголю») | ні |
| Бюджет | кнопки-діапазони, повторне натискання знімає вибір | ні |
| На коли | date (не раніше завтра) | ні |

Згорнуто під «Додати деталі»: привід (select), алкоголь (без / шампанське / вино / міцний), отримання (самовивіз Жмеринка / Жмеринка / Вінниця / область / Нова пошта) + адреса, фото-приклад (до 3, стискаються в браузері). Чекбокс «Мені виповнилося 18 років» — лише якщо обрано алкоголь, тоді обов'язковий. Приховані: `ref` (букет-приклад з `?ref=`), honeypot.

Рівноцінна альтернатива формі — блок «Простіше написати?» з кнопками месенджерів (на телефоні під заголовком, на комп'ютері збоку). Текст повідомлення збирається з того, що вже заповнено.

## 5. Модель даних

`app/data/bouquets/<slug>.json` (slug = ім'я файлу):

```jsonc
{
  "id": 14,                          // порядковий номер, показується як «Букет №14»
  "title": "Червоні тюльпани з Ferrero",
  "date": "2026-02-23",              // коли зроблено
  "price": 1200,                     // грн, ціна цього букета
  "images": ["14/1", "14/2"],        // базові імена в public/images/bouquets/, перше — головне, без фону
  "video": "14/reel",                // опційно
  "occasions": ["birthday", "march8"],
  "recipients": ["woman"],
  "alcohol": null,                   // напр. "Шампанське Bolgrad 0.75"; не null → бейдж 18+
  "shippable": false,                // можна відправити НП (поки не виводиться в UI)
  "size": "M",                       // S / M / L / XL, TODO(мама) підтвердити шкалу
  "composition": ["Ferrero Rocher — 15 шт", "Цукерки-тюльпани з гофропаперу"],
  "description": "",                 // опційно, 1–3 речення
  "featured": true                   // показувати на головній
}
```

Довідники в `app/data/site.ts`: `occasions` (slug → назва), `recipients`, `budgetRanges`. Тип `Bouquet` — в `app/data/types.ts`; під час білду перевіряти, що всі `occasions`/`recipients` є в довідниках і `id` не повторюються (інакше збірка падає).

## 7. API `/api/order` (Nitro server route)

- `POST multipart/form-data`.
- Основа — `server/api/lead.post.ts` з sadovi-mrii (clean/escapeHtml, honeypot, перевірка телефону, лог замість Telegram, якщо бот не налаштований), розширена полями з §4.4 і файлами.
- Фото-референси стискаються в браузері (до ~1600 px, JPEG/WebP, ~1 МБ) перед відправкою; на сервері — ліміт кількості й розміру.
- Захист від спаму: honeypot + Cloudflare Turnstile (лічильник по IP у пам'яті Worker'а не працює надійно).
- Відправка в Telegram Bot API:
  - `sendMessage` — відформатована заявка (HTML parse mode, екранувати ввід користувача);
  - `sendMediaGroup` / `sendPhoto` — референси, якщо є.
- ENV: `NUXT_TELEGRAM_BOT_TOKEN`, `NUXT_TELEGRAM_CHAT_ID` (кілька id через кому — мама і син), `NUXT_TURNSTILE_SECRET`. Бот окремий від інших проєктів. Токен **ніколи** не потрапляє на клієнт.
- Відповідь `{ ok: true }` / помилка з людським текстом. На фронті — стан завантаження, повторна відправка заблокована.
- Fallback: якщо API впав — показати кнопки месенджерів з текстом заявки для копіювання.

## 11. Дизайн

- **Не схожий на Процков Буд і Садові мрії:** інша структура блоків, інші компоненти, інші шрифти (не Unbounded, Golos Text, Geologica, Onest).
- Настрій: теплий, «домашній преміум», не дешевий кондитерський кітч. Багато повітря, великі фото букетів.
- Спільні правила з сусідніх проєктів: без ALL-CAPS лейблів, без «великих цифр» на кшталт «500+ букетів», без шаблонних анімацій при завантаженні, без вигаданих відгуків і фактів.
- Палітра: кремовий/молочний фон, акцент — пильно-рожевий або винний (перегукується з букетами), текст — темний шоколадний, не чистий чорний. Світла тема основна; темна — не обов'язкова.
- Шрифти (Google Fonts, з кирилицею): заголовки — серіф з характером (напр. Cormorant / Playfair Display / Lora), текст — Manrope / Inter / Nunito Sans.
- Mobile-first: більшість трафіку з телефонів (Instagram, Google на мобільному). Перевірка на 360px ширині.
- Ніяких кастомних курсорів, автоплей-музики, важких анімацій. Одна легка анімація при завантаженні: арка з букетом на першому екрані «розгортається» (лише CSS, вимикається при `prefers-reduced-motion`). Решта — лише реакції на дії (hover, відкриття).
- Фірмовий елемент: фото букетів в арці («віконце» подарункової коробки), бирка з ціною на першому екрані.
- Доступність: контраст AA, фокус-стани, label у всіх полів, `alt` у всіх фото.
